# README 이미지

README 상단 스크린샷 자리는 **마크업만 넣어져 있고 주석 처리돼 있다**(`README.md`, `README.ko.md`).
이미지를 여기에 넣고 주석 표시(`<!--`, `-->`)만 지우면 된다.

주석으로 둔 이유: 없는 이미지를 가리키는 `<img>`는 GitHub과 nuget.org 양쪽에서 **깨진 이미지**로 나온다.
그건 스크린샷이 아예 없는 것보다 나쁘다.

## 필요한 파일

| | |
|---|---|
| 경로 | `docs/images/screenshot.png` |
| 폭 | 1600~1800 px 권장 (README에서 900 px로 표시) |
| 형식 | PNG |
| 크기 | 500 KB 이하가 바람직 — 리포에 들어가고 nuget.org에서도 로드된다 |

## 무엇을 찍을까

**UI 컨트롤 라이브러리에서 스크린샷은 기능 목록보다 먼저 읽힌다.** 이 프로젝트를 다른 에디터와
구분해 주는 것이 한 화면에 들어가는 게 좋다:

1. **툴바** (`RichEditorView`의 기본 크롬)
2. **표** — 특히 **중첩 표**와 **인라인 표**(글자처럼 취급). 이게 이 라이브러리의 차별점이다
3. 서식이 섞인 본문 — 제목, 목록, 색, 하이퍼링크
4. 이미지 하나
5. **페이지 보기** 경계선 (A4로 두면 워드프로세서처럼 보인다)

데모 앱에 샘플 문서가 들어 있으므로 대개 그대로 쓸 수 있다:

```
dotnet run --project samples/AvaloniaRichEditor.Demo/AvaloniaRichEditor.Demo.csproj
```

창을 1600x1000 정도로 키우고, 위 요소가 보이는 위치로 스크롤한 뒤 **창만** 캡처한다
(바탕화면·작업 표시줄이 들어가지 않게).

## 넣은 뒤

`README.md`의 URL은 **절대 경로(raw.githubusercontent.com)를 유지할 것.** 이 파일은 패키지 README
(`PackageReadmeFile`)라서 nuget.org가 리포 상대 경로를 해석하지 않는다 — 상대 경로로 바꾸면
패키지 페이지에서만 조용히 깨진다. `README.ko.md`는 패키지에 들어가지 않으므로 상대 경로가 맞다.

이미지는 `main`에 올라간 뒤에야 raw URL로 잡히므로, nuget.org 쪽 표시는 **다음 릴리스부터** 반영된다.
