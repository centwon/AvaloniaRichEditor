# 외부 앱 육안검증 체크리스트

라운드 4~8이 바꾼 **나가는 바이트**를 Word · HWP · 브라우저에서 확인한다.

> **왜 이게 필요한가**: 이 프로젝트의 reader는 자기 writer의 잘못된 출력을 관대하게 읽어낸다.
> 자체 왕복 테스트는 자기 자신과 합의할 뿐이라 이 결함들을 **구조적으로 볼 수 없다.**
> 라운드 4~8의 결함 중 여럿이 실제로 사람이 Word/HWP에 붙여넣다가 발견됐다.

## 생성

```bash
dotnet run --project tools/rtfgen
```

출력: `rtfgen/bin/Debug/net10.0/out/` 에 `.rtf` 4개 + `.html` 4개.

## 여는 방법

| 파일 | Word | HWP | 브라우저 |
|---|---|---|---|
| `*.rtf` | ✅ | ✅ | — |
| `*.html` | ✅ (열기) | — | ✅ |

`.html`은 브라우저와 Word 양쪽에서 봐야 한다. 브라우저가 통과해도 Word의 HTML 해석은 다르다.

## 01-kitchen-sink

| # | 항목 | 통과 기준 | 실패하면 되돌아갈 곳 |
|---|---|---|---|
| 1 | 연속 공백 | `사이에[    ]공백` 의 대괄호 사이가 **4칸**. 공백만 있는 문단이 빈 줄로 남아 있음 | 라운드4 HTML `&nbsp;` |
| 2 | 하이퍼링크 색 | 링크가 **초록색**. 파란색이면 실패 | 라운드4 `data-are-fg` |
| 3 | 목록 | 1/2/3단계가 계단식으로 들여쓰기됨. 마커(`•`, `1.`)가 **본문 글자로 섞이지 않음**. 마커 뒤 간격이 줄 끝까지 튀지 않음. 목록이면서 제목인 항목이 둘 다 유지 | 라운드8 RTF 마커, 라운드4 `data-are-h` |
| 4 | 저자가 넣은 빈 줄 | 두 문단 사이 빈 줄이 **정확히 하나** | 라운드4 `data-are-empty` |
| 5 | 문단 서식 | 가운데/오른쪽 정렬이 각각 맞고, **그 다음 왼쪽 정렬 줄이 오른쪽으로 따라가지 않음**(HWP 고유 함정). 들여쓰기·위아래 여백·배경색이 보임 | 라운드8 `\ql` 명시, 문단 여백 |
| 6 | 이미지 | 블록 이미지가 자기 줄에 있고 **앞 문단에 달라붙지 않음**. 이미지 **아래 빈 줄이 생기지 않음**. 인라인 아이콘이 글자 줄 안에 있음 | 라운드4 `data-are-opens`, RTF `\par` |
| 7 | 구분선 | 가로선이 **선으로** 보임(빈 줄이면 실패) | 라운드4 `\brdrb` |
| 8 | 인라인 표 | 두 표가 글자 줄 안에 있고 **전폭(100%) 블록으로 깔리지 않음** | HTML 인라인 표 `width` |

## 03-tables

| # | 항목 | 통과 기준 | 되돌아갈 곳 |
|---|---|---|---|
| 10 | 테두리 | **모든 셀에 테두리가 보임**. Word/HWP에서 테두리가 아예 없던 자리 | `\clbrdr*` |
| 11 | 병합 | 가로 2칸·세로 2칸 병합 안에 **내부 선이 없음** | `\clmgf`/`\clvmgf` |

| 13 | 셀 안 문단 서식 | 가운데/오른쪽/글머리/제목이 셀 안에서도 유지. 전부 왼쪽 평문이면 실패 | 라운드8 셀 `\pard` |
| 14 | 셀 안 여러 문단 | 두 문단이 **두 줄**로 남음(한 줄로 합쳐지면 실패) | 라운드8 HTML `<br>` |
| 15 | 셀 안 이미지 | 셀 안에 그림이 보임 | |
| 16 | 중첩 표 | 부모 셀의 **'앞 문단'이 중첩 첫 칸에 빨려들지 않고**, **'뒤 문단'이 사라지지 않음** | `\nestcell`/`\itap` |
| 17 | 표 뒤 이미지 | 이미지가 표 **뒤**에 있음(앞으로 올라가면 실패) | 라운드4 `FinalizeTable` |
